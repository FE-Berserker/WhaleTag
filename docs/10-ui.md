# 10. UI 外观与主题

> 11 种主题模式(3 经典 + 8 策划)+ 13 套配色预设(`PRESETS`)+ 快捷切换 + `'system'` 解析约束 + WCAG AA 对比度底线(§3);读屏 / 键盘 / 输入法约定见 §15。

## 1. ThemeMode 联合类型

定义在 [src/renderer/reducers/settings/types.ts](../src/renderer/reducers/settings/types.ts)(**不是** presets.ts),即 settings slice 的 `themeMode` 字段。共 **11 个值**:

**经典(3)**:light / dark / system

**策划(8)**:`warm-paper` / `midnight-plum` / `frosted-mint` / `deep-ocean` / `dawn-blush` / `forest-ink` / **`soft-amber`** / **`high-contrast`**

策划主题通过 [src/renderer/theme/presets.ts](../src/renderer/theme/presets.ts) 的 `THEME_MODE_PRESET_MAP` 绑定固定的 `(mode, presetId)`:

| ThemeMode | mode | presetId | 渲染主色(浅 / 深) |
|---|---|---|---|
| `light` | light | `whale` | `#0a7bae` |
| `dark` | dark | `whale` | `#818cf8` |
| `system` | dynamic | `whale` | 跟随 OS |
| `warm-paper` | light | `warm-paper` | `#b35209` |
| `midnight-plum` | dark | `midnight-plum` | `#c084fc` |
| `frosted-mint` | light | `frosted-mint` | `#0e8276` |
| `deep-ocean` | dark | `deep-ocean` | `#38bdf8` |
| `dawn-blush` | light | `dawn-blush` | `#d52674` |
| `forest-ink` | dark | `forest-ink` | `#34d399` |
| `soft-amber` | light | `soft-amber` | `#7c6f46` |
| `high-contrast` | light | `high-contrast` | `#000000` |

> 注意:策划主题的"主色"上面列的是该主题**实际渲染**的颜色(已是 `mode` 对应侧的 `primary`,不是 preset 表里的浅 / 深双值)。浅色侧的数值是**为满足 WCAG AA 压暗后**的最终值(见 §3),不是品牌原始色。

## 2. 解析与持久化

**`settings.themeMode`** 走 redux-persist。`useResolvedTheme(themeMode)` hook 返回 `{ mode: ResolvedThemeMode, presetId: string }`,其中 `ResolvedThemeMode = 'light' | 'dark'`(字面联合,非 `Exclude<...>`):

- 解析值**只派生,不持久化**(`'system'` 不会粘在退出时的明暗上)
- 经典 `system` 订阅 `matchMedia('(prefers-color-scheme: dark)')`,实时跟随 OS;策划主题不订阅(固定 mode)
- `safeMatchMedia` try/catch,jsdom / 测试环境回退 `'light'`
- **持久化值在运行时视为不可信**:[src/renderer/theme/mode.ts](../src/renderer/theme/mode.ts) 的 `isThemeMode(value)` 是唯一校验入口(3 个经典值 + `THEME_MODE_PRESET_MAP` 的**自身**键;`__proto__` / `constructor` 之类原型链属性不算合法)。`useResolvedTheme` 对非法值回退 `{ mode: 'light', presetId: DEFAULT_PRESET_ID }`(不再可能返回 `undefined` 的映射);`migrateAppearance` 同样把损坏 / 已删除的未来模式归一成 `'light'`,**只在非法时才分配新对象**(合法值返回原引用,守住 `autoMergeLevel1` 逐键比较的前提,见 [09-known-issues](./09-known-issues.md) 的 rehydration 一节)

**`useResolvedThemeMode(mode)`** 是 `useResolvedTheme` 的便捷包装,只返回 `mode`(用于只需传给 `ExtensionViewPanel` 等消费者)。

### ⚠️ 关键约束:`'system'` 与策划主题模式绝不能直接流入 `createTheme.palette.mode`

MUI `createTheme` 只认 `'light' | 'dark'`,传其他值会抛对比度错误。防线:

1. **工厂签名收窄**:`createWhaleTheme(mode: 'light' | 'dark', presetId, fontSize = 13)` —— 漏解析是**编译错误**(`'light' | 'dark'` 字面类型)
2. **Root.tsx 解析**:`useResolvedTheme` 是唯一把这些原始模式转成实际 `(mode, preset)` 的地方

**易漏点**:`src/renderer/containers/MainLayout.tsx` 把主题传给 `ExtensionViewPanel`(prop 类型 `'light'|'dark'`,透传给扩展 iframe)。**必须** `useResolvedThemeMode(themeMode)` 后再传,否则:

- TS 编译错误(宽 `ThemeMode` 不能赋给窄 `'light' | 'dark'`)
- 扩展 iframe 收到 `'system'` 等字符串无法解析,在深色 OS / 策划深色主题下仍按浅色渲染

## 3. 底层配色预设

[src/renderer/theme/presets.ts](../src/renderer/theme/presets.ts) 维护 `PRESETS`(`whale` + 12 个主题预设)+ `THEME_MODE_PRESET_MAP`:

- **`PRESETS` 数组共 13 项**:`whale`(默认)+ 8 个策划(`warm-paper` / `midnight-plum` / `frosted-mint` / `deep-ocean` / `dawn-blush` / `forest-ink` / **`soft-amber`** / **`high-contrast`**)+ 4 个老预设(`ocean` / `forest` / `sunset` / `mono`,保留以备 themePreset 字段反向兼容,**不再映射到任何 ThemeMode**)
- **`PresetPaletteVariant`** token 集:`primary` / `secondary` / `primaryLight` / `backgroundDefault` / `backgroundPaper` / `border` / `text` / `textSecondary` / `hover`
- 中性色**默认**来自 `LIGHT_NEUTRALS` slate / `DARK_NEUTRALS` zinc(浅色 `textSecondary = #64738a`):`whale` / `ocean` / `forest` / `sunset` / `mono` 只覆盖 `primary` / `secondary` / `primaryLight` / `backgroundDefault` / `backgroundPaper`,其余 token 靠展开共用;**8 个策划预设各自覆盖整套** `border` / `text` / `textSecondary` / `hover`(纸感、薄荷、琥珀、高对比尤其明显)
- **WCAG AA 对比度底线**:每套预设的 `primary` 与 `textSecondary` 对 `backgroundDefault` **和** `backgroundPaper` 都要 ≥ 4.5:1;全局 focus outline 取该侧 `primary`,且对两个背景都 ≥ 3:1。浅色侧因此把品牌色按"刚好达标"的量压暗(如 whale `#0ea5e9` → `#0a7bae`),`presets.test.ts` 对 13 套预设 × 明暗双变体逐个断言 —— 改色时以它为准,别凭眼睛调
- `primaryLight` 深色可带 alpha(如 `#818cf820`),活动位置背景 16% 底色
- `getPreset(id)` 对未知 / undefined id 回退 `PRESETS[0]`(`whale`)

## 10. ConfirmDialogProvider(window.confirm 替代,2026-07-22)

`src/renderer/components/ConfirmDialogProvider.tsx`:`useConfirm()` 返回 `confirm({ message, title?, confirmLabel?, danger? }) => Promise<boolean>`,渲染 MUI 确认框(随主题、支持 danger 红钮),替代原生 `window.confirm`(不随主题、阻塞渲染进程)。挂载在 **Root.tsx(IOActionsContextProvider 之上)**——所以 MainLayout 内所有组件 + IO 层的回收站失败回退确认都能用。一次只开一个:后到的 confirm 把前一个按 `false` 结算。已迁移 8 处:删除单/批量(useListCommands)、删除位置(Sidebar)、删除文件夹(DirectoryTree)、删除标签组(TagGroups)、回收站失败回退(IOActions)、侧车问题提示(file-list/SidecarIssuesAlert)、`McpSection`、`RevisionHistoryDialog`。`useConfirmOptional()` 是给会被测试裸挂载的 provider 的宽容变体(无 Provider 时回退 window.confirm)。

> **无 `title` 也必有可读标题**:MUI 只在自己能找到 `DialogTitle` 时才挂 `aria-labelledby`,所以 provider 在调用点没传 `title` 时仍渲染 `DialogTitle`(文案取 `confirmTitle`,五套 locale 均有)。删除位置 / 删除标签组 / MCP 令牌重置 / 删除单文件 / 批量删除这些只传 `message` 的调用点因此都有可访问名;显式传 `title` 时照旧覆盖。

> `alert()`(ExtensionHost 的 2 处:重命名前的未保存提醒与保存失败)未迁移 —— 纯告知无分支,语义不同;如需统一可后续换 notice 通道。

## 11. 失败可见性:错误展示约定(2026-11)

2026-11 审计发现 15 处"失败不可见":写操作失败后 UI 表现为"没变化",搜索失败后继续显示上一次的结果,目录加载失败后显示成空目录。统一成三条规则:

- **变更类失败 → 组件本地 Snackbar / Alert**.打标(PropertiesTray 快捷行、EntryContextMenu 周期标签与移除标签)、MCP 开关、删除历史版本、添加位置时的原生选择器,全部把真实 message 交给已有的 notice/`Alert` 通道;`void ipcApi.x()` 一律补 `.catch(...)`,不再留下未处理 rejection。属性托盘的重命名失败除 IOActions 的全局通知外也走本地 sink(FileList 传 `onError={showNotice}`,失败后输入框回滚成原文件名);Sidebar 的"新建 Excalidraw / Draw.io"与右键"在文件管理器中显示"改走 `app-notice`,不再 `.catch(() => undefined)` 静默。
- **列表类失败 → 清旧数据 + 错误态 + Retry**.[SearchBar](../src/renderer/components/SearchBar.tsx) 与 [AdvancedSearchDialog](../src/renderer/components/AdvancedSearchDialog.tsx) 失败时先清空结果再显示错误与 Retry,绝不拿上一查询的结果冒充本次;[DirectoryTree](../src/renderer/components/DirectoryTree.tsx) 把加载失败记为 `childrenError`,在展开节点下渲染错误行(`folderLoadFailed` + 真实错误 tooltip + Retry),不再缓存空数组充当"空目录"。
- **查询进行中要能看出"在查"**:[AdvancedSearchDialog](../src/renderer/components/AdvancedSearchDialog.tsx) 在请求未返回时禁用 Search 按钮、标题下显示 `LinearProgress`、结果区标 `aria-busy`;另用单调序号丢弃旧请求晚到的结果(错误也按序号判断),避免"上一次查询的结果盖住本次"。命中超过 300 条时仍只渲染前 300 条以守 §12 的渲染成本,但顶部显式提示已截断(`resultsTruncated`),不再静默丢结果。
- **后台维护失败 → 带 tag 的 `console.warn`**(不可操作、不该弹 toast):启动清理 revision、fulltext 路径同步、外部改动重载编辑器 tab、窗口状态探测。

共享件:[errors.ts](../src/renderer/services/errors.ts) 的 `errorMessage(unknown)`;[app-notice.ts](../src/renderer/services/app-notice.ts) + [AppNoticeHost.tsx](../src/renderer/components/AppNoticeHost.tsx) 是给没有本地 Snackbar 的 surfaces(侧边栏操作条等)用的应用级通道,挂在 `Root.tsx`;listener 抛错被隔离。新增文案 `operationFailed` / `searchFailed` / `folderLoadFailed` / `retry` 已补齐 en / zh / zh-TW / ja / ko 五套 locale(en 为 fallback)。

> 测试:树的展开规则抽到 [directory-tree-rows.ts](../src/renderer/domain/directory-tree-rows.ts) 后可不挂载虚拟列表直测;`app-notice` / `errors` 也有独立单测(见 docs/19 P1-10)。

**应用级通知是队列,不是单槽**:[AppNoticeHost.tsx](../src/renderer/components/AppNoticeHost.tsx) 一次只显示一条,但后续提示排在后面逐条展示,不再互相覆盖;当前条以 `key={notice.id}` 重挂载 Snackbar,让每条提示都按自己的 `autoHideDuration`(error 8s / 其余 5s)重新计时,而不是沿用上一条的倒计时。排队规则抽成 [app-notice.ts](../src/renderer/services/app-notice.ts) 的纯函数 `enqueueNotice(queue, notice)`:已显示的队头不参与裁剪,待显示项最多保留最新的 3 条(`MAX_NOTICE_QUEUE`),队列满时丢最旧的待显示项而不是当前条。关闭(自动超时或点 ×)只消费队头,下一条立即顶上来。

## 12. 长列表渲染成本(2026-11)

[CalendarView.tsx](../src/renderer/components/CalendarView.tsx) 的**议程视图**早已用扁平行 + 窗口化渲染(`AgendaRow`);未窗口化的是**月视图单日格子**:每格是独立滚动容器,一个装了几千个文件的目录仍会在每格 `entries.map` 出全部行。窗口化单格需要给每格单独引一层虚拟列表(嵌套滚动 + 拖拽命中判定都要重做),风险与收益不匹配,故改用 CSS 层面优化:

- `CalendarEntryItem` 根节点加 `content-visibility: auto` + `containIntrinsicSize: '0 28px'` —— 滚出视口的行跳过布局与绘制,滚动条高度保持稳定(预留 40px 会让月视图滚动跳变);DOM 仍保留,拖拽/命中行为不变。
- 这不改变用户可见内容;真正窗口化留作后续(需要重做 DayCell 的嵌套滚动与 drop 目标)。

> 同理:[ThumbIcon.tsx](../src/renderer/components/ThumbIcon.tsx) 在 `cacheKey` 变化时清空上一张图,避免复用单元格短暂显示别的文件的缩略图。

- **多选拖拽**:[file-cell.ts](../src/renderer/components/file-cell.ts) 的 `buildFileDragItem` 在 react-dnd 真正开始拖拽时读取当前 `selectedPathsRef`,不再让 `useMemo` 缓存原地修改的旧 Set;选中变化后无需复制整个 Set 也能拿到正确拖拽集合。
- **只读位置上的拖放不静默无效**:把标签或文件拖进只读位置时,[useListCommands.ts](../src/renderer/hooks/useListCommands.ts) 的 `handleDropTag` / `handleDropFiles` 先弹 `readOnlyLocation` warning 再返回。
- **带标签新建**(看板 / 甘特 / 矩阵列头的「新建文件 / 文件夹」):条目创建成功但标签写入失败时不算整体失败——条目已经建好,此时弹 `createdTagWriteFailed` warning 并照常刷新列表;只有创建本身失败才 reject。判定在 [IOActionsContextProvider.tsx](../src/renderer/hooks/IOActionsContextProvider.tsx) 的纯函数 `createTaggedEntryCore` 里(与导入的 `importTagWriteFailed` 同一处理方式)。
- **属性托盘的编辑缓冲跨刷新保留**:[PropertiesTray.tsx](../src/renderer/components/PropertiesTray.tsx) 的描述 / 重命名缓冲只跟随「当前选中的条目」(按路径识别)。保存触发的目录刷新会让 entries 换新引用,但同一条目刷新时:正在编辑的描述框保持输入内容,未聚焦时才回填最新存储值;开着的重命名框与其中的名字不被关闭。选中换成另一个条目时两块缓冲才重置。
- **批量移动 / 删除**:[useListCommands.ts](../src/renderer/hooks/useListCommands.ts) 逐项执行 IO 时传 `{refresh:false,treeRefresh:false}`,整批结束后只刷新一次当前目录;目录树仅对实际成功项的源目录（移动另含目标目录）按路径去重刷新,失败项不贡献刷新路径。所有成功/失败聚成一条 notice,`composeBatchNotice` 统一全成功/部分成功/全失败的文案与级别;部分成功用五语言 `partialFailure` 单模板组合,批量删除的成功文案通过 `trashedItems` / `deletedItems` 带真实成功 count。错误通知只展示前 3 条并以 `andMoreFailures` 汇总剩余数量,完整错误数组输出到控制台;失败项保留选择,最终 refresh 失败也可见。`refreshTree` 是 `IOActionsContextValue` 的必填依赖,FileList 不再用 no-op 兜底;旧测试替身必须显式提供。把目录移入自身或子孙目录作为该项目的错误报告,不再静默跳过混合批次中的非法项；单文件操作保持原 tree + listing 语义。
- **Gallery 多选打标**:多目标统一走 `saveMany`,等待所有 sidecar 写入 settle 后只刷新一次并报告真实更新数量。部分失败仍 reject,但携带 `updatedCount` 与完整 `errors`;`Error.message` 最多前三条加省略号，避免其他调用点出现超长 Snackbar。通知复用 `composeBatchNotice` 显示真实成功数、前三条错误和剩余数量,完整错误保留到控制台,刷新失败也不吞错。
- **选择计数区分"可见目标"与"被筛选隐藏"**:[FileList.tsx](../src/renderer/components/FileList.tsx) 的 `selectedEntries` 取自 `visible`(`filterEntriesByTag` 之后),批量删除 / 移动 / 打包消费的正是它;头部改由 [FileListHeader.tsx](../src/renderer/components/FileListHeader.tsx) 导出的 `SelectionSummary({ selectedCount, hiddenSelectedCount })` 呈现 —— 主计数 `nSelected` 只数当前筛选下**仍可见**的选中行,被筛选隐藏的选中项另用 `nSelectedHidden`(五语言)单独说明。隐藏项的选择**保持有效**(撤销筛选即恢复),但永不进入批量命令,也不会被静默计入删除 / 移动 / 打包;两者都为 0 时不渲染,任一 > 0 才出现"清空选择"按钮。
- **Lightbox**:[FileList.tsx](../src/renderer/components/FileList.tsx) memoize playlist,避免每次 render 都让 Lightbox memo 失效;[MediaLightbox.tsx](../src/renderer/components/MediaLightbox.tsx) 胶片条最多渲染当前项附近 41 个 cell,前后翻页按钮可直达远程窗口,点击 cell 或键盘导航后回到当前项窗口,不会把长播放列表截断成只能浏览 41 项。缩放拖拽的 window mousemove/mouseup 监听由 [media-pan.ts](../src/renderer/components/media-pan.ts) 返回幂等 disposer,在 mouseup、重复 mousedown、Esc、关闭/切换媒体与 unmount 时统一解绑,旧手势不会误删新手势监听。

## 15. 无障碍:读屏、键盘与输入法(2026-11)

交互层新增控件时直接照这几条做(主题色 / 对比度见 §3,焦点环见 §9):

- **图标按钮必须有名字**:只有 Tooltip 包图标的按钮对读屏是匿名的。[FileToolbar](../src/renderer/components/FileToolbar.tsx) 的上 / 后退 / 前进 / 最近 4 个导航按钮、[Sidebar](../src/renderer/components/Sidebar.tsx) 的添加位置与"新建 Excalidraw / Draw.io"、[TagGroups](../src/renderer/components/TagGroups.tsx) 的分组开关都补了 `aria-label`(分组开关另带 `aria-expanded`);对话框用 `aria-labelledby` 指向 `DialogTitle`([McpApprovalDialog](../src/renderer/components/McpApprovalDialog.tsx))。视角切换按钮的先例在 §9。
- **开关不再复述状态**:设置页通用的两个 Switch(显示隐藏文件 / 显示农历)去掉恒显 "Enabled" 的 `FormControlLabel` 文案 —— 状态本来就由 `checked` 表达,原文案只会让读屏把开关念成 "Enabled"。四个 Switch(通用三个 + "任务提醒")各自挂 `slotProps={{ input: { 'aria-label': t(...) } }}`,可访问名取自对应的 i18n label(`deleteToTrash` / `showHiddenFiles` / `showLunar` / `taskReminder`);行标题 `Field` 只是视觉分组(没有 `htmlFor`),名字必须来自 Switch 自身 —— 新增开关照此办理。
- **可聚焦的非输入控件要真能操作**:[PropertiesTray](../src/renderer/components/PropertiesTray.tsx) 的列宽拖拽点补 `role="separator"` + `tabIndex={0}` + `aria-orientation="vertical"` + `aria-valuemin` / `aria-valuemax` / `aria-valuenow`(260 / 600),`←` 变宽、`→` 变窄,每步 10 px,与鼠标拖拽共用同一对上下界(越界只夹紧,不越限)。
- **焦点环用主题色**:[SettingsDialog](../src/renderer/components/SettingsDialog.tsx) 的快捷键搜索框从硬编码 rgba 边框 + `outline: none` 换成 `&:focus-visible { outline: 2px solid <primary>; outlineOffset: 2 }`,并补 `aria-label`(键 `keybindingsSearch`);颜色因此随主题变化,且满足 §3 的 ≥3:1。
- **默认不占用 Tab**:[keybindings.ts](../src/renderer/domain/keybindings.ts) 的默认映射不再把 `Tab` 绑到 `switchView`,旧持久化里的 `Tab: switchView` 在迁移时丢弃,保证键盘用户能把焦点移出文件列表(WCAG 2.1.2);需要循环视角的用户在设置里显式绑定。
- **标签与调色板可键盘操作**:[TagLibrary](../src/renderer/components/TagLibrary.tsx) 的标签 chip、[TagGroups](../src/renderer/components/TagGroups.tsx) 的分组头 / 移除按钮、[WorkflowManagerDialog](../src/renderer/components/WorkflowManagerDialog.tsx) 的形状与颜色 swatch 均为 `role="button"` + `tabIndex=0` + Enter / Space;调色板改为 `Menu` + `MenuItem`,方向键走 MUI 菜单语义。
- **画廊键盘自持**:[GalleryView](../src/renderer/components/GalleryView.tsx) 对方向键 / Home / End / Enter / Space 在 `preventDefault()` 后 `stopPropagation()`,不再与外层 [FileList](../src/renderer/components/FileList.tsx) 的 `handleKeyDown` 同时处理同一个键;未处理的键(Delete / F2 / Esc / 视角切换)继续冒泡给列表。
- **输入法组合期一律不提交**:[ime-guard.ts](../src/renderer/components/ime-guard.ts) 的 `isImeComposing(e)`(`nativeEvent.isComposing === true` **或** `keyCode === 229`)在 `Enter` 语义处早退 —— 否则中日文用户在候选框里按 Enter 会被当成"确认改名 / 提交标签"。已接入:[Row](../src/renderer/components/Row.tsx) 行内重命名、PropertiesTray 的重命名与描述 `Ctrl+Enter`、[InlineTagInput](../src/renderer/components/InlineTagInput.tsx) 的 Enter / Space、[PromptDialog](../src/renderer/components/PromptDialog.tsx)、[AddLocationDialog](../src/renderer/components/AddLocationDialog.tsx)、[SearchBar](../src/renderer/components/SearchBar.tsx)、[WorkflowManagerDialog](../src/renderer/components/WorkflowManagerDialog.tsx);`Escape` 取消不受影响。
- **语言与区域设置只认一处**:[Root.tsx](../src/renderer/containers/Root.tsx) 把 `settings.language` 先写到 `document.documentElement.lang`(读屏发音与断词),再 `i18n.changeLanguage`;[format.ts](../src/renderer/services/format.ts) 的绝对日期与 [RevisionHistoryDialog](../src/renderer/components/RevisionHistoryDialog.tsx) 的时间戳都显式传 `i18n.language`,不再跟随 OS 默认区域。
- **外壳按钮同样要有名字**:只有 Tooltip 包层的图标按钮在 2026-11 审计里仍是一批匿名控件,[TitleBar](../src/renderer/components/TitleBar.tsx)(最小化 / 最大化-还原 / 关闭)、[Sidebar](../src/renderer/components/Sidebar.tsx)(回收站 / 设置 / 移除位置)、[SearchBar](../src/renderer/components/SearchBar.tsx)(内容搜索开关带 `aria-pressed`、高级搜索)、[RevisionHistoryDialog](../src/renderer/components/RevisionHistoryDialog.tsx)(恢复 / 删除)与 [SettingsDialog](../src/renderer/components/SettingsDialog.tsx) 的"添加全文本路径"都补了 `aria-label`,名字与 Tooltip 文案同源,均为 i18n 键。
- **嵌套交互要拆成同级**:[Sidebar](../src/renderer/components/Sidebar.tsx) 的位置行不再把删除 `IconButton` 套进 `ListItemButton`(按钮套按钮会让 Tab 焦点落在哪、Enter 触发谁都不确定)。外层 `Box` 只承担拖拽源 / drop 目标 / `data-loc-row` / 右键菜单,行本身的 `ListItemButton` 与删除按钮成为兄弟节点;删除仍 `stopPropagation()`,不会顺带打开位置。行的可访问名因此含位置名与路径 secondary 文本(如 "Docs /docs");行容器不是 `<li>`,列表容器一并改为 `component="div"`,避免 `ul > div` 的非法嵌套。
- **设置左侧导航是真 tablist**:11 个分类是 `role="tab"` + `aria-selected` + `aria-controls`(指向右栏 `role="tabpanel"` 的 `id`),只有当前 tab 在 Tab 序列里(`tabIndex` 0 / -1);`↑` / `↓` 循环移动、`Home` / `End` 跳到首尾并即时切换(自动激活,不需要再按 Enter),焦点随选中一起走。
- **尊重 reduced-motion**:[theme/index.ts](../src/renderer/theme/index.ts) 在 `MuiCssBaseline` 的 `styleOverrides` 里用 `@media (prefers-reduced-motion: reduce)` 把 `*, *::before, *::after` 的 `animation-duration` / `transition-duration` 压到 `0.01ms !important`(动画只跑一轮),`scroll-behavior` 改 `auto`;新增动效不必逐处判断,系统级偏好自动生效。

## 16. 局域网面板与移动端界面(2026-11)

桌面端「设置 > 局域网」([LanSettings.tsx](../src/renderer/components/LanSettings.tsx),分类 key `lan`、标签 `settingsSectionLan` / 中文「局域网」,顺序排在 MCP 服务器之后、命令之前)与手机端页面是同一功能的两半,前端行为见 [docs/22-lan-access.md](./22-lan-access.md)。

- **面板结构**:标题 + 说明 caption;固定一条 warning `Alert`(同一 Wi-Fi / 只读 / 令牌仅本次会话有效),不随状态隐藏;`role="status"` 的状态文字;一个 contained 小按钮承担启动 / 停止,请求进行中 `disabled` 并换文案;运行时显示 base URL——多网卡用 `Select`(label `lanBaseUrl`),单网卡用纯文本,长 IPv6 用 `overflowWrap: anywhere` 防溢出;`Copy` 按钮带 `aria-label`(键 `lanCopyLink`),复制成功后在 `role="status"` 的行里提示,颜色取 `success.main`;二维码是 220×220 的 `<img>`。
- **二维码编码器按需加载**:`import('qrcode')` 只在「运行中 + 已有 URL」时执行,停止时不加载,首屏 settings bundle 不含它(成本考量同 §12)。
- **配对链接是 `<baseUrl>#token=<URL 编码后的 token>`**:token 只进剪贴板与二维码编码器,面板**不**把它渲染成可读文本。截图面板不会泄漏,但截图二维码或转发剪贴板链接等同于交出这次会话的凭据。
- **面板每 2000ms 轮询 `lan:getStatus`**:主进程可能因网卡地址变化或位置增删自动停止(服务端行为见 docs/22 §7),轮询把状态和二维码一起收回,避免用户对着已失效的二维码扫;组件卸载即清定时器。任一次轮询成功都会清掉上一条状态错误;连续 3 次失败(`MAX_POLL_FAILURES`)后停止轮询并保留最后一次错误 + `Retry`(重读状态并重启轮询),既不假装还在轮询,也不因主进程不可达每 2 秒刷一条提示。
- **失败展示沿用 §11**:状态查询 / 启停 / 复制 / 二维码各自本地 `Alert` + `errorMessage()` 的原始信息,不静默、不静默重试;可重试的失败(状态轮询、二维码编码)给 `Retry` 动作,启停 / 复制这类由按钮自身重试的失败不给按钮,避免两个入口做同一件事。
- **移动端界面**([src/mobile/App.tsx](../src/mobile/App.tsx)):单列移动布局,组件用 MUI 默认主题 + 自己的 [styles.css](../src/mobile/styles.css),**不接**桌面主题与配色预设(§1–§3),页面 `theme-color` 固定 `#1976d2`;顶部「只读访问」`Chip`,位置 `Select`,面包屑 + 返回,搜索框与标签 chips,列表 / 网格 `ToggleButtonGroup`,预览 `Dialog`。索引缺失用 warning `Alert`(搜索与标签暂不可用,先在桌面建索引),会话失效(401)统一回配对页。胶囊 chip、系统字体栈等设计约定仍守 §14,但没有桌面侧的三栏布局与虚拟列表。
- **无障碍**:两个界面都靠原生 `Button` / `IconButton` 与可见文案操作,二维码带 `alt`,状态文字用 `role="status"`;新增控件照 §15 的 `aria-label` 约定补名字。
