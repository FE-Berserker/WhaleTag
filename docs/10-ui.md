# 10. UI 外观与主题

> 11 种主题模式(3 经典 + 8 策划)+ 13 套配色预设(`PRESETS`)+ 快捷切换 + `'system'` 解析约束。

## 1. ThemeMode 联合类型

定义在 [src/renderer/reducers/settings/types.ts](../src/renderer/reducers/settings/types.ts)(**不是** presets.ts),即 settings slice 的 `themeMode` 字段。共 **11 个值**:

**经典(3)**:light / dark / system

**策划(8)**:`warm-paper` / `midnight-plum` / `frosted-mint` / `deep-ocean` / `dawn-blush` / `forest-ink` / **`soft-amber`** / **`high-contrast`**

策划主题通过 [src/renderer/theme/presets.ts](../src/renderer/theme/presets.ts) 的 `THEME_MODE_PRESET_MAP` 绑定固定的 `(mode, presetId)`:

| ThemeMode | mode | presetId | 渲染主色(浅 / 深) |
|---|---|---|---|
| `light` | light | `whale` | `#0ea5e9` |
| `dark` | dark | `whale` | `#818cf8` |
| `system` | dynamic | `whale` | 跟随 OS |
| `warm-paper` | light | `warm-paper` | `#b45309` |
| `midnight-plum` | dark | `midnight-plum` | `#c084fc` |
| `frosted-mint` | light | `frosted-mint` | `#14b8a6` |
| `deep-ocean` | dark | `deep-ocean` | `#38bdf8` |
| `dawn-blush` | light | `dawn-blush` | `#db2777` |
| `forest-ink` | dark | `forest-ink` | `#34d399` |
| `soft-amber` | light | `soft-amber` | `#7c6f46` |
| `high-contrast` | light | `high-contrast` | `#000000` |

> 注意:策划主题的"主色"上面列的是该主题**实际渲染**的颜色(已是 `mode` 对应侧的 `primary`,不是 preset 表里的浅 / 深双值)。

## 2. 解析与持久化

**`settings.themeMode`** 走 redux-persist。`useResolvedTheme(themeMode)` hook 返回 `{ mode: ResolvedThemeMode, presetId: string }`,其中 `ResolvedThemeMode = 'light' | 'dark'`(字面联合,非 `Exclude<...>`):

- 解析值**只派生,不持久化**(`'system'` 不会粘在退出时的明暗上)
- 经典 `system` 订阅 `matchMedia('(prefers-color-scheme: dark)')`,实时跟随 OS;策划主题不订阅(固定 mode)
- `safeMatchMedia` try/catch,jsdom / 测试环境回退 `'light'`

**`useResolvedThemeMode(mode)`** 是 `useResolvedTheme` 的便捷包装,只返回 `mode`(用于只需传给 `ExtensionViewPanel` 等消费者)。

### ⚠️ 关键约束:`'system'` 与策划主题模式绝不能直接流入 `createTheme.palette.mode`

MUI `createTheme` 只认 `'light' | 'dark'`,传其他值会抛对比度错误。防线:

1. **工厂签名收窄**:`createWhaleTheme(mode: 'light' | 'dark', presetId, fontSize = 13)` —— 漏解析是**编译错误**(`'light' | 'dark'` 字面类型)
2. **Root.tsx 解析**:`useResolvedTheme` 是唯一把这些原始模式转成实际 `(mode, preset)` 的地方

**易漏点**:`src/renderer/containers/MainLayout.tsx` 把主题传给 `ExtensionViewPanel`(prop 类型 `'light'|'dark'`,透传给扩展 iframe)。**必须** `useResolvedThemeMode(themeMode)` 后再传,否则:

- TS 编译错误(宽 `ThemeMode` 不能赋给窄 `'light' | 'dark'`)
- 扩展 iframe 收到 `'system'` 等字符串无法解析,在深色 OS / 策划深色主题下仍按浅色渲染

## 3. 底层配色预设

[src/renderer/theme/presets.ts](../src/renderer/theme/presets.ts) 维护 `PRESETS`(`whale` + 12 个主题预设)+ `THEME_MODE_PRESET_MAP`:

- **`PRESETS` 数组共 13 项**:`whale`(默认)+ 8 个策划(`warm-paper` / `midnight-plum` / `frosted-mint` / `deep-ocean` / `dawn-blush` / `forest-ink` / **`soft-amber`** / **`high-contrast`**)+ 4 个老预设(`ocean` / `forest` / `sunset` / `mono`,保留以备 themePreset 字段反向兼容,**不再映射到任何 ThemeMode**)
- **`PresetPaletteVariant`** token 集:`primary` / `secondary` / `primaryLight` / `backgroundDefault` / `backgroundPaper` / `border` / `text` / `textSecondary` / `hover`
- 浅色共用 `LIGHT_NEUTRALS` slate 中性色;深色共用 `DARK_NEUTRALS` zinc 中性色;每套预设只改 `primary` / `primaryLight`
- `primaryLight` 深色可带 alpha(如 `#818cf820`),活动位置背景 16% 底色
- `getPreset(id)` 对未知 / undefined id 回退 `PRESETS[0]`(`whale`)

## 5. 状态字段

- `themeMode: ThemeMode`(11 值,老值 `'light'/'dark'/'system'` 向后兼容)
- `themePreset: string` **保留但 Root 不读**(Root 直接读 `themeMode` 经 `useResolvedTheme` 派生 presetId);保留仅为了向后兼容历史 settings 与外部消费者
- 字段级迁移:`if (base.themePreset === undefined) base = { ...base, themePreset: DEFAULT_PRESET_ID }`

## 8. 文件夹缩略图回归修复

[ThumbIcon.tsx](../src/renderer/components/ThumbIcon.tsx) 是所有视图(网格 / 列表 / 画廊 / Mapique / 日历 / 属性托盘)里文件夹缩略图的**唯一渲染路径**。原守卫 `if (entry.isDirectory || !canThumb) return` 把所有目录提前返回,导致 `loadFolderThumbnail` 死代码。改为只对**不可缩略的文件**短路(允许目录走 IntersectionObserver + doLoad)。

## 10. ConfirmDialogProvider(window.confirm 替代,2026-07-22)

`src/renderer/components/ConfirmDialogProvider.tsx`:`useConfirm()` 返回 `confirm({ message, title?, confirmLabel?, danger? }) => Promise<boolean>`,渲染 MUI 确认框(随主题、支持 danger 红钮),替代原生 `window.confirm`(不随主题、阻塞渲染进程)。挂载在 **Root.tsx(IOActionsContextProvider 之上)**——所以 MainLayout 内所有组件 + IO 层的回收站失败回退确认都能用。一次只开一个:后到的 confirm 把前一个按 `false` 结算。已迁移 5 处:删除单/批量(useListCommands)、删除位置(Sidebar)、删除文件夹(DirectoryTree)、删除标签组(TagGroups)、回收站失败回退(IOActions)。`useConfirmOptional()` 是给会被测试裸挂载的 provider 的宽容变体(无 Provider 时回退 window.confirm)。

> `alert()`(ExtensionHost 保存失败等 3 处)未迁移 —— 纯告知无分支,语义不同;如需统一可后续换 notice 通道。

## 11. 失败可见性:错误展示约定(2026-11)

2026-11 审计发现 15 处"失败不可见":写操作失败后 UI 表现为"没变化",搜索失败后继续显示上一次的结果,目录加载失败后显示成空目录。统一成三条规则:

- **变更类失败 → 组件本地 Snackbar / Alert**.打标(PropertiesTray 快捷行、EntryContextMenu 周期标签与移除标签)、MCP 开关、删除历史版本、添加位置时的原生选择器,全部把真实 message 交给已有的 notice/`Alert` 通道;`void ipcApi.x()` 一律补 `.catch(...)`,不再留下未处理 rejection。
- **列表类失败 → 清旧数据 + 错误态 + Retry**.[SearchBar](../src/renderer/components/SearchBar.tsx) 与 [AdvancedSearchDialog](../src/renderer/components/AdvancedSearchDialog.tsx) 失败时先清空结果再显示错误与 Retry,绝不拿上一查询的结果冒充本次;[DirectoryTree](../src/renderer/components/DirectoryTree.tsx) 把加载失败记为 `childrenError`,在展开节点下渲染错误行(`folderLoadFailed` + 真实错误 tooltip + Retry),不再缓存空数组充当"空目录"。
- **后台维护失败 → 带 tag 的 `console.warn`**(不可操作、不该弹 toast):启动清理 revision、fulltext 路径同步、外部改动重载编辑器 tab、窗口状态探测。

共享件:[errors.ts](../src/renderer/services/errors.ts) 的 `errorMessage(unknown)`;[app-notice.ts](../src/renderer/services/app-notice.ts) + [AppNoticeHost.tsx](../src/renderer/components/AppNoticeHost.tsx) 是给没有本地 Snackbar 的 surfaces(侧边栏操作条等)用的应用级通道,挂在 `Root.tsx`;listener 抛错被隔离。新增文案 `operationFailed` / `searchFailed` / `folderLoadFailed` / `retry` 已补齐 en / zh / zh-TW / ja / ko 五套 locale(en 为 fallback)。

> 测试:树的展开规则抽到 [directory-tree-rows.ts](../src/renderer/domain/directory-tree-rows.ts) 后可不挂载虚拟列表直测;`app-notice` / `errors` 也有独立单测(见 docs/19 P1-10)。

## 12. 长列表渲染成本(2026-11)

[CalendarView.tsx](../src/renderer/components/CalendarView.tsx) 的**议程视图**早已用扁平行 + 窗口化渲染(`AgendaRow`);未窗口化的是**月视图单日格子**:每格是独立滚动容器,一个装了几千个文件的目录仍会在每格 `entries.map` 出全部行。窗口化单格需要给每格单独引一层虚拟列表(嵌套滚动 + 拖拽命中判定都要重做),风险与收益不匹配,故改用 CSS 层面优化:

- `CalendarEntryItem` 根节点加 `content-visibility: auto` + `containIntrinsicSize: '0 40px'` —— 滚出视口的行跳过布局与绘制,滚动条高度保持稳定;DOM 仍保留,拖拽/命中行为不变。
- 这不改变用户可见内容;真正窗口化留作后续(需要重做 DayCell 的嵌套滚动与 drop 目标)。

> 同理:[ThumbIcon.tsx](../src/renderer/components/ThumbIcon.tsx) 在 `cacheKey` 变化时清空上一张图,避免复用单元格短暂显示别的文件的缩略图。
